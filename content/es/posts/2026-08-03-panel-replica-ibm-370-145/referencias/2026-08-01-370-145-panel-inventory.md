# IBM System/370 Model 145 — Console Lamp and Switch Inventory

**Design document · 2026-08-01 · os370 panel replica project**

Complete inventory of every indicator, switch, key and meter on the IBM 3145 system control
panel, with the Hercules mapping for each. This is the build specification for the acrylic panel
and the Arduino firmware.

Companion documents: [`2026-08-01-references.md`](2026-08-01-references.md) §20 (why the /145 was
chosen) and §3.2 (the manual set).

The manual presents the console in this order, which is also the physical top-to-bottom,

| 6 | **A-Register Display roller switch** | 13 | **32-bit data display — the operator-useful one** |

| 10 | **Rate switch** | 17 | **Run / single-instruction step** |

#### Findings that change the build

1. **The panel is built on an 18-position module.** System Checks (2 × 18), CPU Status (18) and
   Console File (18) are all exactly 18 wide. That is a strong layout constraint and a gift for
   the artwork: one repeated grid pitch, and it corroborates the proportions in §7.5.
2. **Unlabelled positions are real lamp positions, not blank panel.** They are drawn the same size
   as labelled ones — physically present holders for features not installed. **Build all 18 per
   row**; light only the labelled ones.
3. **IBM colour-codes the lenses:** `R` = red (all check/fault indicators), `A` = amber
   (TEST, TOD CLOCK INVLD, IMPL REQD, and every parity lamp), unmarked = white. **This is directly
   actionable** — buy three LED colours, not one, and match the original.
4. **Parity lamps exist in three places:** 4 per roller bank (8 total) and 1 in the Console File
   Register. All amber. See §4.5 of the wiring plan for how to drive them honestly.

### 3.1 System Indicators — the five main lamps ✅

Panel legend row: **`SYS  MAN  WAIT  TEST  LOAD`**

| Lamp | IBM's definition (quoted) | Drivable? | Source of truth |
| --- | --- | --- | --- |
| **SYSTEM** | "on when CPU operations are in progress and either use meter is running" | ✅ Yes | Hercules CPU started and executing |
| **MANUAL** | "on when the CPU clock is stopped or the system is in a soft-stop state. All pending interrupts are handled. **Manual store/display operations are possible only when the MANUAL indicator is on**" | ✅ Yes | Hercules CPU stopped |
| **WAIT** | "on when the system is in a wait state (CPU clock running but no instruction processing taking place). If an interrupt occurs, the CPU is taken out of wait state and processing is started under control of the program being executed" | ✅ Yes | **PSW wait bit** |
| **TEST** | "on when any of the following switches are not in the process or normal position: 1. RATE, 2. CHECK CONTROL, 3. DIAGNOSTIC/CONSOLE FILE CONTROL, 4. ADDRESS COMPARE CONTROL" | ✅ Yes — **locally** | **Pure OR of four of our own switch positions. Needs no emulator data.** |
| **LOAD** | "on when the Initial Program Load (IPL) is in progress. It turns on when the LOAD key is pressed and turns off when the initial PSW is loaded successfully" | ✅ Yes | Set on `ipl`, clear when the CPU runs from the loaded PSW |

**All five are drivable.** These are the lamps that matter most to a viewer and they cost almost
nothing to get right.

### 3.2 CPU Status Indicators ✅ (definitions) / ⚠️ (exact lamp count)

The manual defines eight by name. A note states: *"Indicators not described in the chart are for
service personnel and are described in maintenance documentation."*

| Lamp | IBM's definition | Drivable? | Notes |
| --- | --- | --- | --- |
| **EXE CPLT** | "Indicates CPU stopped state reached as a result of: 1. Pressing the STOP key. 2. The RATE switch in the INSTRUCTION STEP position. 3. A match being detected while in the address match mode of operation." | ✅ Yes | Set when Hercules stops for any of those three reasons — all three are things we cause |
| **ADR COMP MATCH** | "Indicates that the address (real or logical) being used to access main storage matches the address set into switches CDEFGH during an address match operation. The action taken by the CPU as a result of the match condition is controlled by the setting of the ADDRESS COMPARE CONTROL switch." | ✅ Yes | Hercules breakpoint hit |
| **CLOCK STOP** | "Indicates that the CPU is in an immediate stop condition (CPU clock not running)." | ⚠️ Partial | Distinguishes *immediate* (hard) stop from soft stop. Hercules has only one stopped state — map to hard-stop switch positions |
| **TOD CLOCK INVLD** | "Indicates that the time-of-day clock is invalid. The indicator is turned off by successfully executing a set clock instruction." | ⚠️ Partial | Architected concept; Hercules TOD is always valid. Light briefly after reset for authenticity |
| **LOG PRES** | "Indicates that a log is present in the log area of main storage. When the CHECK CONTROL switch is in the STOP AFTER LOG position and the LOG PRES indicator is on, run SEREP." | ❌ No | Machine-check logout. No Hercules equivalent |
| **SNG ECC CHK** | "Indicates that one of the data or check bits from storage has been corrected." | ❌ No | Real ECC hardware |
| **CF PWR ON** | "Indicates that power is applied to the console file." | ✅ Trivially | Console diskette power — just light it whenever the panel is powered |
| **IMPL REQD** | "Indicates that an operation which resulted in a system reset has been initiated. The indicator is turned off when the system reset routine is executed. An IMPL is required if the indicator remains on." | ✅ Yes | Pulse on `sysreset`, clear when reset completes |

⚠️ The panel artwork row appears to hold roughly **eighteen** lamp positions in this bank, of
which these eight are customer-documented. Legend fragments recoverable from the artwork include
`ADR`, `EXE COMP`, `CLOCK`, `STOR`, `TRAP`, `INV ADR`, `TOD`, `SNG`, `CF`, `M2`, `X-LATE`,
`CLOCK`, `LOG`, `ECC`, `PWR`, `IMPL`. ❓ **Exact count and legend order must be read off the
scan.**

### 3.3 System Check Indicators ⚠️

The manual gives only: *"If a system check indicator is on, refer to the system check error
recovery procedure."* — no per-lamp table, because these are diagnostic.

Legend fragments recoverable: `SYSTEM CHECKS`, `CLOCK`, `DIAGN`, `M-REG PARITY CHECK`, `STOR`,
`SEL`, `CYCLE`. Two rows of lamps, roughly **twelve plus five** in the upper group and
**eighteen** in the lower.

**Drivable? ❌ No.** These report 3145 hardware faults. Hercules has no failing hardware.
→ Treat as decorative; see [§7.2](#72-what-to-do-with-undrivable-lamps).

### 3.4 Console File Indicators ⚠️

Two groups: **`CONSOLE FILE`** (sub-labels `DISK`, `CPU`) and **`CONSOLE FILE REGISTERS`**,
roughly **nineteen** positions total.

The manual says: *"Re-IMPL when any console file check indicator is on"* and, of the register
group, *"These indicators are used by service personnel."*

**Drivable? ❌ No**, except `CF PWR ON` in §3.2. The console file is the 3145's microcode diskette
drive, which Hercules does not model.

## 4. Roller displays

Both rollers show **four bytes** (Byte 0 … Byte 3) across a bank of lamps, with the roller drum
selecting which internal source feeds them.

### 4.1 A-Register Display roller switch ✅ — **the operator-useful one**

Legend on the drum, as printed:

```
A REGISTER DISPLAY
 1  STORAGE/EXT REGS
 2  DOCUMENTARY CNSL
 3  S,P,T,L REGISTERS
 4  SYSTEM REGISTER
 5  CHAN INTERFACE
 6  CHAN WORD A
 7  CHAN WORD B
 8  CHAN WORD C
```

IBM's content table:

| Position | Contents | Use |
| --- | --- | --- |
| **1** | **Storage or External Register**, selected by the STORAGE SELECT switch | **Customer** |
| 2–8 | TI/TA/TT/TE registers; S/P/T/L registers; System Register bytes 0–2 + H-Register; MPX channel registers or selector-channel external word GTAG; Channel Word A (GSTAT); Channel Word B (GBS); Channel Word C (GBUF) | **"Positions 2 through 8 are for service use"** |

**Two critical statements from the manual:**

> "Position 1 is described in the Store/Display section of this manual."

> **"When the CPU is in a soft-stopped state (MANUAL indicator on), the indicators display the
> next instruction address."**

That second sentence is the single most valuable line in the whole manual for this project: it
means the main display bank shows **the PSW instruction address** whenever the machine is
stopped — which is exactly what Hercules gives us, for free, at every breakpoint and single step.

⚠️ **OCR caveat:** the drum legend list and the content table did not align cleanly in the text
layer, so the exact position↔content mapping for positions 2–8 is uncertain. Since all of 2–8 are
service-use and undrivable, this does not affect the build — but ❓ confirm visually if you want
the drum legend silkscreen to be exactly right.

### 4.2 Display Assembler Out roller switch ✅

Legend on the drum, as printed:

```
DPLY ASSEMBLER OUT
 1  M REGISTER
 2  SDBO
 3  CONTROL REGISTER
 4  MB2,MB3,N2,N3
 5  B REGISTER
 6  Z REGISTER
 7  D REGISTER
 8  MC REGISTER
```

| Position | Byte 0 | Bytes 1–3 | Use |
| --- | --- | --- | --- |
| **1** | Protect stack key associated with the address in bytes 1,2,3 | **M-Register bytes 1, 2, 3** | Customer |
| **2** | Displays the selected channel | **Storage Data Bus-Out** | Customer |
| 3 | — | C-Register | Service ∗ |
| 4 | MB-2 | MB-3, N2, N3 | Service ∗ |
| 5 | — | B-Register | Service ∗ |
| 6 | — | Z-Register | Service ∗ |
| 7 | — | D-Register | Service ∗ |
| 8 | — | MCKA | Service ∗ |

∗ IBM's footnote: *"Positions 3 through 8 are for service use."*

**Drivable? Mostly ❌.** The M-Register, SDBO, C/B/Z/D registers and MCKA are 3145
microarchitecture — they do not exist in Hercules. Positions 1 and 2 could be given plausible
synthetic content derived from real storage traffic; positions 3–8 cannot be driven honestly at
all.

> **The key ratio.** Across both rollers, **2 of 16 positions** carry operator-relevant,
> architected content — and both of those are drivable. This is precisely why the /145 was chosen
> over the /155, /165 or /168, whose extra rollers are almost entirely microarchitectural.

### 5.3 Address Compare switch ✅

Match occurs "when the address used to access main storage matches the address set in console
switches CDEFGH, and the STORAGE SELECT switch is set to the MAIN STORAGE position." The action on
match is set by the ADDRESS COMPARE CONTROL toggle.

| Position | IBM's definition | Use |
| --- | --- | --- |
| **ANY (Real Address)** | "used for normal program processing. With the switch in this position, a match occurs for main storage access when the storage address matches the address set in console switches CDEFGH" | Customer |
| **DATA STORE** | "allows a match when the storage address matches the address set in console switches CDEFGH during a data store operation" | Customer |
| **I/O (INPUT/OUTPUT)** | "allows a match when the storage address matches … and the operation is storing or fetching data for an I/O operation" | Customer |
| **I-COUNTER (Real or Logical Address)** | "causes a match when the real or logical main storage address matches the address in console switches CDEFGH, and the operation is an instruction fetch from main storage" | Customer |
| **DATA COMPARE TRAP** | "used to determine what instruction is causing a particular storage byte location to be modified" | Customer |
| **ANY (Logical Address)** | "allows a match when the logical main storage address used to access storage matches the address set in console switches CDEFGH" | Customer |
| Remaining (`CTRL WORD ADR` etc.) | "for service personnel" | Service |

**Maps to Hercules breakpoints.** The instruction-fetch, data-store and any-access variants
correspond to genuinely different breakpoint semantics — a rich, faithful mapping.

### 5.7 Rotary switches A through H ✅ — eight hex wheels

The workhorse input of the panel. Eight hexadecimal rotary switches, read in groups depending on
the operation.

| Switches | Label | Function (IBM) |
| --- | --- | --- |
| **A, B** | `DATA` | "Specifies the value of data to be entered on manual store operations." |
| **C, D** | `CF ADDRESS` | "Specifies the track/sector address of the console file on certain diagnostic microprogram load operations." |
| C–H | `CONSOLE FILE` | "Provides a service function described in the maintenance documentation." |
| E–H | `BYTE COUNT` | Service |
| **F, G, H** | `MAIN STORAGE ADDRESS` | "Specifies the main storage address for manual store/display operations **and for address compare switch functions**." |
| F, G, H | `CONTROL STORAGE ADDRESS` | "Used by service personnel to specify a control storage address for manual store/display and address compare functions." |
| **H** | `WORD ADDRESS` | "Used to display General-Purpose and Floating-Point Registers." |
| — | **`LOAD UNIT ADDRESS`** | **"Specifies the load-unit address for Initial Program Load (IPL) operations."** |
| — | `STORE/DISPLAY ADDRESS` | "Used to store/display local storage." |
| — | `BYTE/X-LATE REGS` | "Specifies the byte to be altered during manual store operations." |

From the store/display procedure, the WORD ADDRESS encoding is: `00` = General-Purpose Register 1,
`01` = GPR 2, `04` = GPR 5 — i.e. the wheel value selects the register, offset by one.

⚠️ The panel legend strip beneath the wheels came through OCR as fragments
(`A CONSOLE FILE ADDRESS | C … BYTE COUNT D | E | F WORD ADDRESS G | BYTE X-LATE REGS`, with a
second line `STORE/DISPLAY ADDRESS`). ❓ **The exact letter-to-legend registration must be read off
the scan before silkscreening**, since the strip spans the wheels and the groupings overlap.

#### ✅ Resolved: LOAD UNIT ADDRESS is wheels **F, G, H**

Confirmed from [SR20-4460-0](https://www.bitsavers.org/pdf/ibm/370/SR20-4460-0_System_370_Operators_Reference_Guide_Jul74.pdf),
Model 145 IPL procedure:

> "Load and ready the System Resident (SYSRES) device. **Dial the address of the IPL device into
> LOAD UNIT ADDRESS switches FGH.** Press the LOAD key. After an automatic system reset, the IPL
> operation starts and the LOAD indicator turns on."

and, from the secondary-nucleus procedure: "Set the **three** LOAD UNIT ADDRESS switches to the
SYSRES address."

**What these wheels actually select.** They do *not* pick "a disk" by name. They dial a
**three-hexadecimal-digit I/O device address** — the S/370 channel-and-unit address of whatever
device you want to IPL from. That is normally the **DASD volume holding SYSRES**, but the same
switches can address a tape drive or card reader; IPL from tape was the standard way to install a
system. So: *yes, in practice these are the "which disk do I boot from" wheels*, but architecturally
they are a general device-address selector.

**Firmware mapping.** Read F, G, H as three hex digits, compose the address, and issue
Hercules `ipl <cuu>` — or `iplc` if ENABLE SYSTEM CLEAR is held, matching the /168's
"Press ENABLE SYSTEM CLEAR and LOAD simultaneously" idiom. Under MVS Turnkey the SYSRES volume is
conventionally at address `148`, so the wheels would read **1 4 8**.

Note also that the /145 IPL performs "an automatic system reset" *before* loading — so the panel
should show MANUAL/IMPL behaviour briefly, then LOAD, then running.

### 5.8 Use meters ✅

"Two direct reading use meters record operating time. One meter records **customer** operating
time and the other records **service** time. The position of the **key switch** determines which
of the two meters is to record operating time. Your service representative has the key for this
switch."

> "The meters record only CPU operating time. The meters run for manual store and display
> operations because these operations start the CPU clock. Either meter runs for a minimum of
> approximately one second each time the meter is started."

**Drivable? ✅** — from Hercules CPU-busy time. Fit real hour meters, or emulate with a small
display. Note the one-second minimum dwell: an authentic detail worth reproducing.

### 7.2 Audit: lamps that **cannot** be honestly driven from Hercules

This is the full list. A lamp is undrivable when the thing it reports either **does not exist in
an emulator** (physical hardware, fault detection, microcode) or is **3145-specific
microarchitecture** rather than S/370 architecture. Anything Hercules cannot produce, you must not
pretend it produces.

#### Group A — System Check Indicators bank · **entire bank, ~30 lamps** ❌

Legends recoverable from the artwork: `CLOCK`, `DIAGN`, `M-REG PARITY CHECK`, `STOR`, `SEL`,
`CYCLE`, plus others ❓ unread.

**Why undrivable:** every one reports a *3145 hardware fault* — clock failure, M-register parity
error, storage check, selector-channel check. **Hercules has no failing hardware**, so there is no
condition to report. The manual's only guidance is "If a system check indicator is on, refer to the
system check error recovery procedure." On a healthy emulated machine, the correct state of this
entire bank is **dark, permanently**.

#### Group B — Console File Indicators · **~19 lamps** ❌

`CONSOLE FILE` (`DISK`, `CPU`) and `CONSOLE FILE REGISTERS`.

**Why undrivable:** the console file is the 3145's **microcode diskette drive**. Hercules loads no
microcode and has no diskette. IBM's own note on the register group: "These indicators are used by
service personnel."

**One exception:** `CF PWR ON` ("Indicates that power is applied to the console file") is honestly
drivable — light it whenever the panel is powered, because that statement is then simply true.

#### Group C — CPU Status Indicators · the hardware/RAS subset ❌

| Lamp | Why it cannot be driven |
| --- | --- |
| **LOG PRES** | Reports a machine-check **logout present in main storage locations 128–704**. Hercules generates no machine checks, so no logout is ever written. |
| **SNG ECC CHK** | "one of the data or check bits from storage has been corrected" — **real ECC memory hardware**. Emulated storage does not develop bit errors. |
| **DIAGNOSTIC STOP** | Per the SYSTEM RESET key description: "Any error detected by system reset turns on the DIAGNOSTIC STOP indicator." Hercules' reset never fails, so this lamp can never legitimately light. |
| ~10 further undocumented lamps in this bank ❓ | IBM: "Indicators not described in the chart are for service personnel." Fragments include `M2`, `X-LATE`, `STOR`, `TRAP`, `INV ADR`. |

**Two that are architected but effectively static — drive with care:**

- **TOD CLOCK INVLD** — architected (turned off by a successful `SET CLOCK`), but Hercules' TOD
  clock is always valid. Honest treatment: light it after a system reset and clear it on the first
  `SET CLOCK`, which is exactly the real behaviour.
- **CLOCK STOP** — "the CPU is in an immediate stop condition (CPU clock not running)". Hercules
  has only **one** stopped state, whereas the 3145 distinguishes immediate (hard) stop from soft
  stop. Honest treatment: light it only when the RATE or CHECK CONTROL switch is in a HARD STOP
  position, since that is a state you genuinely know.

#### Group D — Display Assembler Out roller · **~32 lamps, nearly all positions** ❌

| Position | Content | Verdict |
| --- | --- | --- |
| 1 — byte 0 | **Storage protect key** for the displayed address | ✅ **Drivable** — storage keys are *architected* and Hercules models them |
| 1 — bytes 1–3 | **M-Register** | ❌ 3145 internal register |
| 2 | **Storage Data Bus-Out**, byte 0 = selected channel | ⚠️ Synthesizable — you know the last byte actually read from storage; the *bus* is fictional but the *data* is real |
| 3 | C-Register | ❌ Microarchitecture |
| 4 | MB-2, MB-3, N2, N3 | ❌ Microarchitecture |
| 5 | B-Register | ❌ Microarchitecture |
| 6 | Z-Register | ❌ Microarchitecture |
| 7 | D-Register | ❌ Microarchitecture |
| 8 | MCKA | ❌ Microarchitecture |

IBM's footnote confirms positions 3–8 are service-only. **This whole bank is the panel's biggest
honesty problem** — 32 prominent lamps, of which one byte is truly drivable.

#### Group E — A-Register Display roller · **positions 2–8** ❌

TI/TA/TT/TE registers; S/P/T/L registers; System Register bytes 0–2 + H-Register; MPX channel
registers / selector-channel external word `GTAG`; Channel Word A (`GSTAT`); Channel Word B
(`GBS`); Channel Word C (`GBUF`).

**Why undrivable:** 3145 internal registers and *physical channel interface words*. Hercules
implements channels functionally (it moves the data) but does not model these hardware words.

**Position 1 is the exception and is fully drivable** — storage or registers per STORAGE SELECT,
and the next instruction address whenever MANUAL is lit. See [§4.1](#41-a-register-display-roller-switch--the-operator-useful-one).

#### Group F — Backlit keys with no counterpart ❌

| Key | Why |
| --- | --- |
| **START CONSOLE FILE** | Backlights red → white → off during a console-diskette read. No diskette exists. |
| **SET CONTROL STORAGE ADDRESS** | Addresses **control storage** — i.e. microcode store. Hercules has none. |
| **CHECK RESET** | "Resets all machine check circuitry." There is no machine-check circuitry to reset. |

| --- | --- | --- |

### 7.3 What to do about them

Three defensible policies, in order of preference:

1. **Leave them dark.** Strictly correct — a healthy machine shows no system checks, and IBM's own
   documentation says a lit check indicator means "run the error recovery procedure". Visually
   flat, but unimpeachable.
2. **Synthesize only where the underlying data is real.** Display Assembler Out position 2 (SDBO)
   can show bytes genuinely read from storage; the roller can be driven from real instruction
   throughput. The *bus* is fictional, the *traffic* is not.
3. **Static plausible pattern** for the service banks — clearly a display prop, not a claim.

**Never** drive check or fault lamps from a random-number generator. A panel that shows storage
parity errors during normal operation is not a replica, it is a lie about the machine's state, and
anyone who operated a 3145 will spot it immediately.

**Whichever policy you pick, state it plainly in the project README** and reproduce this audit
there. Everyone who knows these machines will ask which lamps are real; a precise answer lands far
better than a vague one — and "about 40 % are real, here is exactly which" is a genuinely
impressive answer.

### 7.4 Firmware behaviour rules

Rules taken directly from the manual — implementing these is what separates a replica from a
light show:

- **Gate store/display on MANUAL.** "Manual store/display operations are possible only when the
  MANUAL indicator is on." Reject STORE and DISPLAY while the CPU is running.
- **Compute TEST locally.** OR of: RATE ≠ PROCESS, CHECK CONTROL ≠ PROCESS,
  DIAGNOSTIC/CONSOLE FILE CONTROL ≠ PROCESS/IMPL, ADDRESS COMPARE CONTROL ≠ SYNC/NORM.
  **No emulator round-trip.**
- **A-Register display follows CPU state.** When MANUAL is lit, show the next instruction address.
  Otherwise show whatever STORAGE SELECT + roller position 1 selects.
- **START is context-dependent.** Free-run when RATE = PROCESS; single instruction when
  RATE = INSTRUCTION STEP; resume from breakpoint when stopped on an address match.
- **EXE CPLT has exactly three causes** — STOP key, INSTRUCTION STEP, address match. Do not light
  it for anything else.
- **LAMP TEST works at any time** and "without affecting system operation" — never route it
  through the Pi.
- **Use meters have a ~1 s minimum dwell** per start.

### 7.5 Panel scale and proportions

**Project decision (2026-08-02): the replica must carry the original's *proportions*, not its
absolute dimensions.** This materially changes the critical path — see the note in
[§8](#8-open-questions).

#### What this unblocks

Absolute dimensions live in the 57 MB FE manual and the parts catalog, and finding them means
hunting through scanned engineering drawings. **Proportions do not require either.** They can be
extracted from sources already in hand, so artwork work can start immediately.

#### Best source for proportions: the manual's own figures

The panel artwork figures in `GA24-3554-0` (pp. 8–22) are **orthographic line drawings** — no
perspective distortion, no lens error. For *within-section* proportions they are better than any
photograph. Each console section is drawn with its lamp rows, switch positions and legend strip in
correct relative placement.

What the figures do **not** reliably give is the **relative placement of the sections to each
other**, since they are drawn one per page. For that you need one overall view:

| Source | Use |
| --- | --- |
| `GA24-3554-0` figures, pp. 8–22 | **Within-section proportions** — lamp spacing, bank grouping, switch placement. Orthographic, so trace directly |
| One straight-on photograph of a complete 3145 console | **Section-to-section placement** and overall aspect ratio |
| [Rhode Island Computer Museum](https://www.ricomputermuseum.org/collections-gallery/interesting_computer_items/ibm-370-panel) · [Computing History UK](https://www.computinghistory.org.uk/det/31058/IBM-System-370-Control-Panel/) | Both hold physical /370 panels — ask for a straight-on photograph, or measurements if they will take them |

A photograph taken at an angle can be perspective-corrected **without knowing any absolute
dimension**, by rectifying against features known to be rectangular (the bezel, the lamp rows).
That is sufficient for proportions and is exactly why this relaxation helps.

#### The constraint that does *not* scale: physical parts

Proportional freedom is not total freedom. Three things have hard minimum sizes, and they set the
floor on how small the panel can be:

| Part | Fixed size | Consequence |
| --- | --- | --- |
| **Pushbutton inserts** | **≈ 25.5 × 25.1 mm** ([3D-printed models](https://www.printables.com/model/165377-ibm-system360-and-370-mainframe-computer-console-p), taken from real IBM parts) | Sets key pitch. The OpenSCAD source *is* parametric, so they can be rescaled — but at their true size they are the most visually authentic element on the panel |
| **LEDs** | 3 mm ⇒ ~4.5 mm minimum pitch · 5 mm ⇒ ~6.5 mm | A 32-lamp roller bank with inter-byte gaps needs ≈ 36 pitches ⇒ **~165 mm (3 mm LEDs)** or **~235 mm (5 mm)** for that element alone |
| **Rotary switches, toggles** | COTS bodies, 6–10 mm bushings, plus knob diameter and finger clearance | Do not shrink at all. Eight hex wheels side by side need real estate regardless of panel scale |

**Consequence: scaling down is where this bites.** Shrink the panel far enough and the lamp banks
stay put while the COTS switches collide, and the proportions break anyway.

#### Recommended method: pick one anchor, derive everything

1. **Choose the anchor dimension first.** Two sensible choices:
   - **Pushbutton pitch at true size (25.5 mm)** — maximum authenticity, larger panel.
   - **Lamp pitch driven by your chosen LED** — smaller panel, buttons rescaled in OpenSCAD to suit.
2. **Measure everything else in the source figures as a ratio to that same feature.**
3. **Multiply through by the anchor.** The panel size falls out; it is an *output*, not an input.
4. **Sanity-check the COTS parts fit** at the resulting scale. If they do not, the anchor was too
   small — go back to step 1.

Record the chosen anchor and scale factor in this document once fixed, so the acrylic artwork, the
LED PCB and the 3D-printed parts are all generated from one number.

### 7.6 Minimum panel size

**Question: how small can the panel be, given the PCB and its components?**

**Answer: the PCB is not the binding constraint. The switches are, and then the LED pitch.**

#### The electronics fit behind almost anything

| Item | Area needed (SMD) | Area needed (through-hole DIP) |
| --- | --- | --- |
| 26 × TPIC6B595 (SOIC-20 ≈ 12.8 × 7.5 mm) + routing | ≈ 47 cm² | DIP-20 is 25.4 × 7.6 mm ⇒ ≈ 100 cm² |
| 16 × 74HC165 (SOIC-16 ≈ 10 × 7.5 mm) + routing | ≈ 25 cm² | ≈ 55 cm² |
| ~464 resistors (0805 = 2 × 1.25 mm) + routing | ≈ 37 cm² | 6 mm axial ⇒ ≈ 150 cm² |
| **Driver electronics total** | **≈ 110 cm² (≈ 105 × 105 mm)** | **≈ 305 cm² (≈ 175 × 175 mm)** |

The **LED board must be at least as large as the lamp array itself**, because each LED sits behind
its own legend position. That array is far larger than 110 cm² at any workable pitch. So put the
driver ICs on the **reverse side of the same board**, or on a daughterboard, and they cost no panel
area at all. **Use SMD** and this is a non-issue.

#### What actually sets the floor

| Element | Hard minimum | Driver |
| --- | --- | --- |
| **Roller display bank** — 32 lamps + 3 byte gaps + drum/legend | **≈ 220 mm** (3 mm LEDs @ 5 mm pitch) · ≈ 300 mm (@ 7 mm) · ≈ 470 mm (5 mm LEDs @ 12.7 mm) | LED pitch |
| **Widest indicator row** — ~33 lamps ❓ | ≈ 165 mm @ 5 mm · ≈ 420 mm @ 12.7 mm | LED pitch |
| **8 hex wheels A–H** | **≈ 128 mm** (16 mm pitch, small 14 mm knobs) · ≈ 200 mm (25 mm pitch, real knobs) | **COTS switch body + finger clearance — does not scale** |
| **5 mode rotaries** with legend arcs | **≈ 190 mm** (38 mm each) | **COTS + legend arc — does not scale** |
| **15 keys** | ≈ 270 mm in one row · **≈ 135 mm in two rows** (18 mm rescaled) · 405 / 205 mm at true 25.5 mm | Button insert size |
| **6 toggles** | ≈ 90 mm | COTS bushing |
| **2 use meters + key switch** | ≈ 80 mm | COTS |
| **Driver PCB** | ≈ 105 × 105 mm, **mounted behind** | Not binding |

**The switch bands bind before the lamps do.** Wheels + mode rotaries alone need ≈ 320 mm of
usable width, and unlike LEDs they cannot be scaled down — a rotary switch body, its knob and the
finger clearance to turn it are fixed physical facts.

#### Proportions couple the two dimensions

Because the layout must stay faithful, **width and height cannot be minimised independently.** With
the original aspect ratio `R = W₀ / H₀`, the required scale is:

```
scale = max( W_min / W₀ ,  H_min / H₀ )
```

and the panel is `scale × (W₀ × H₀)`. Minimising one dimension inflates the other.

#### Working envelope

| Scale | LED / pitch | Keys | Approx. panel | Notes |
| --- | --- | --- | --- | --- |
| **A — floor** | 3 mm @ 5 mm | 18 mm | **≈ 400 × 170 mm** at 2.4:1 | Tight. Switch bands are cramped; verify with a mockup |
| **B — comfortable** | 3 mm @ 6.35 mm (0.25″) | 22 mm | ≈ 520 × 220 mm | Recommended starting point |
| **C — near-authentic** | 5 mm @ 12.7 mm (0.5″) | **true 25.5 mm** | ≈ 1000 × 420 mm | Closest to a real 3145 console. Large, but this *is* roughly the original size |

⚠️ These envelopes assume a ~2.4:1 landscape aspect and the provisional lamp counts. **The true
aspect ratio is not yet known** — it needs the overall photograph described in §7.5. Treat the
table as an order-of-magnitude guide, not a specification.

#### The cheap way to settle it

**Print the traced artwork 1:1 on paper at two or three candidate scales, lay the actual COTS
switches and a strip of LEDs on top, and look at it.** This costs an afternoon and resolves every
clearance question that no amount of calculation will settle reliably. Do this *before* ordering
acrylic or committing a PCB.

### 7.7 Latency requirement

From the Operation Blinkenlights project (references §5.1): a USB I/O board gave ~1 second panel
latency and was unusable; an Arduino Mega 2560 gave **~1 ms**. Treat **≲10 ms** end-to-end as the
design target, and keep all lamp logic that *can* be computed locally — TEST, LAMP TEST, switch
debounce — on the Arduino.

## 9. Hercules configuration for this panel

```
ARCHLVL   S/370        # REQUIRED for MVS 3.8j — functional, not cosmetic
```

`ARCHLVL` genuinely changes the emulated machine (instruction set and addressing mode); `CPUMODEL`
does not — IBM's documentation states it "defines a purely cosmetic value only". MVS Turnkey ships
`CPUMODEL 3033`; changing it to `0145` alters nothing but the reported machine type. See
[`2026-08-01-references.md`](2026-08-01-references.md) §1 and §7.2.
